# SS-PATCH-1.1.25 — Original Parts sources + Biped startup fix

**Install:** Apply directly over **v1.1.24**. This is a changed-files-only patch; do not reinstall other patches. Reload/reopen both SideScroll and Character Lab so `sidescroll-runtime-v135` replaces the older service worker. Existing saved characters, IndexedDB artwork, character selection keys, built-in rigs and clips are not reset.

**Delivered**

- **Saved quadruped Parts assemblies can reference shipped original (`atlas-builtin-*`) deform-atlas meshes.** On an explicit Character Lab Save after a Parts/Setup edit, the app records the *exact geometry* for any referenced built-in meshes into that custom character's existing library document (`legacyAtlasSource`, optional `animlab.legacy-atlas-sources.v1`). The actual PNG remains the existing shipped `fox-deform-atlas-v2.png`; no PNG bytes are placed in localStorage. Newly saved original-only and mixed original/imported Atlas Parts can now load in the game. Rest positions, authored Part transforms, source UVs, validated existing Skin weights, z/draw order and the Fox sparse clips use the existing game mesh renderer. Any unbound or stale Skin part displays at rest with a console warning; no automatic rebind or pose weight regeneration. **This is not yet authorable Biped meshes or a complete unskinned rigid-bone attachment editor.**
- **Mixed Atlas sources** use their original individual image sizes and separate GL textures. Missing custom PNG blocks only characters that actually reference imported meshes. Legacy-only characters work offline using the shipped atlas after the PWA updates.
- **Fix Biped starter readiness regression:** v1.1.24 resolver accepted a Biped without PNG, but game GL setup incorrectly always tried to upload `data.image`. v1.1.25 skips custom texture setup for Biped starters and lets their Hero 1 rigid cutout renderer and saved Walk/Run/Jump clips work as intended. This was verified with synthetic resolver tests; physical Safari/WebGL test is pending.
- **Character chooser:** newly supported legacy-only and mixed assemblies show `Bundled Parts mesh` or `Mixed Atlas pieces`; unavailable old saves explicitly say a new Character Lab Save is needed.
- Optional legacy mesh geometry follows standard Character Library JSON export/import. The *shipped* source PNG is supplied by the game; **imported custom PNGs remain device-local IndexedDB and are NOT carried by JSON backup**.

**Phone checks:** After installing, open Character Lab, choose/create a local quadruped and keep/duplicate an original Part (a source labelled `atlas-builtin-*` in saved data); make a Parts edit and **Save** while the bundled atlas is loaded. In the game, choose that character and test idle/walk/run/jump, facing in both directions, draw order, scale, texture and FPS. For a character with both an original Part and imported Atlas Part, verify both textures show and animate without unexpected UV stretching. Try a Biped starter with no imported PNG: confirm it becomes Ready and runs Walk/Run/Jump with Hero art. Reopen New01 to check imported-only rendering did not regress. Confirm an old original-Parts saved character without the geometry snapshot displays an explanation instead of a wrong character, then save it in Character Lab and reload the game. Finally check game/Character Lab reopening offline on iPhone.

**Still outstanding:** On-iPhone visual parity for all custom character types; fully authored Biped atlas/mesh/rig/skin, simple rigid single-bone assignment UI, source-PNG-inclusive portable backups, animation list/New Animation/action assignment, Climb and Pick Up/Put Down/Carry authored animations and template library. No source images or schemas replaced. Game page must reload after a saved Character Lab edit.

**Verification:** JavaScript syntax checks plus Node synthetic legacy-only/mixed/failed legacy-snapshot/UV/animation resolver tests. No iPhone/Safari or full WebGL acceptance claimed.
