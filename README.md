# SideScroll patch 1.0.151 — Anim Lab Rig Designer v1

Changed-files-only cumulative patch over the agreed **v1.0.150** baseline. v1.0.150 remains the approved baseline until this patch is tested and accepted.

## What this adds

Anim Lab now separates **Rig** (character construction/rest structure) from **Animate** (clip posing). The Fox is the first descriptor-driven quadruped rig.

The saved Fox rest rig contains 21 authored joints:

- Rear Body → Mid Root → Front Body → Neck → Head
- Front Near: Socket → Knee → Paw
- Front Far: Socket → Knee → Paw
- Rear Near: Socket → Hock/Knee → Paw
- Rear Far: Socket → Hock/Knee → Paw
- Tail: Root → Tail 1 → Tail 2 → Tip

Rig Designer v1 includes large grouped joint buttons, direct viewport joint dragging, a precision drag pad, Free/X/Y + Fine modes, live joint coordinates and connected bone lengths, per-joint reset, paired copy, Near→Far / Far→Near copy, Paws to Ground, Reset Rig, optional artwork ghosting, Motion Reference in Rig mode, and the normal Anim Lab Undo/Redo/Save/Discard guard.

One continuous custom drag is one Setup/Rig transaction. Pointer cancel restores the pre-drag working copy. **Only Save persists structural rig data.**

## Runtime / migration safety

Fox rest-rig data is stored under `sidescroll.fox.rig.v2`. An unsaved Rig edit is previewed only in Anim Lab. Gameplay reads the last saved rest rig through `fox-rig.js`.

The new default rig is derived from the geometry actually generated by v1.0.150, including its authored limb segment lengths. It is not derived from the approximate guide knee/foot comments/constants.

Independent comparison against the untouched v1.0.150 module across all 16 Walk + 16 Run + 16 Jump samples found a maximum legacy joint-coordinate delta of **1.11e-16 world units**. Loading v1.0.151 with no existing rig data performs **no `sidescroll.fox.rig.v2` storage write**. Installing the patch alone therefore does not reshape the current Fox.

Existing animation data is not destructively rewritten when proportions change. Existing angle/pose channels are evaluated against the saved rest-bone vectors and lengths, so motion retargets onto the new proportions. Older poses that do not contain the new torso channels receive zero-value defaults.

## Animate additions

Fox Animate now exposes separate:

- Mid Root — existing whole-body vertical motion
- Front Body — chest/front lift
- Rear Body — pelvis/rear lift
- Whole Body Tilt — existing pitch

This allows torso shaping before Stage 4. **No planted-paw / FK-IK solver has been added.**

## Current artwork limitation

The current Fox cutout remains the existing artwork. Legs and other bound segments follow the saved rig, while the torso is still one artwork segment between Rear Body and Front Body. Mid Root is therefore structurally real and visible in Bones, but a true painted mid-spine bend needs the later art-refit/split pass. No replacement production art is invented in this patch.

## Install

Apply this ZIP directly over **v1.0.150**, preserving the flat repository layout. All files belong at repository root.

The runtime/service-worker cache revision is bumped and `anim-lab-rig.js` is part of the install shell. Existing large Motion Reference PNGs remain cache-on-demand.

## Practical iPhone test

1. Open **Anim Lab → Fox → Rig**. Confirm Character Rig / Setup, Rig Designer and Motion Reference are visible; Animate controls/timeline should be inactive.
2. Turn Bones on. Select **Front Near → Socket** and drag the large viewport joint. Confirm the leg follows the socket.
3. Undo once. Confirm the entire continuous drag returns in one step; Redo should restore it.
4. Select a knee/hock, alter it, and confirm the connected bone-length readout changes.
5. Test **Copy to Pair**, **Near → Far**, **Far → Near**, and **Paws to Ground**.
6. Move **Rear Body**, **Mid Root** and **Front Body** separately. Confirm the skeleton shows three independently authored torso points.
7. Toggle **Art Ghost** and use the Walk Motion Reference while judging proportions. Reference playback should be independent in Rig mode and Animate Link disabled there.
8. Make a rig change and confirm **Unsaved** appears. Press **Discard** and confirm the last saved rig returns.
9. Make a clear change again and press **Save**. Leave/reopen Anim Lab and confirm it reloads.
10. Enter Play as Fox and confirm saved rest proportions are used. Existing Walk/Run/Jump should still animate over those proportions.
11. Return to **Animate** and confirm Mid Root / Front Body / Rear Body / Whole Body Tilt are separate controls.
12. Check Hero 1 and Hero 2 still behave as before; they do not receive a structural Rig Designer in this version.
13. Check both direct Play and Home → Play, then close/relaunch the A2HS PWA after the updated service worker has installed.

## Validation performed off-device

- All project JavaScript files pass `node --check`.
- `style.css` parses with no `tinycss2` errors and balanced braces.
- Modified HTML has no duplicate IDs or missing local script/style dependencies.
- All literal Anim Lab `getElementById`/helper ID lookups resolve against the HTML or generated extension markup.
- Service-worker shell references resolve and include `anim-lab-rig.js` exactly once.
- Descriptor: 21 joints, 15 measured bone links, 6 Near/Far symmetry pairs, 4 ground-contact paws.
- v1.0.150 vs v1.0.151 default Fox comparison: 48 sampled poses, max coordinate delta `1.1102230246251565e-16`.
- Empty-storage module load does not create the new rig key.
- Isolated persistence/reload harness confirms a saved rest-rig edit survives a fresh module load.
- Legacy pose objects with no Front/Rear Body channels normalise them to zero without mutating the source pose.
- Walk/Run/Jump geometry remains finite after loading an edited persisted rig.
- Source inspection confirms direct viewport/precision drags begin one transaction, preview during movement, commit once on pointer-up and cancel/restore on pointer-cancel.
- Gameplay `drawRigCharacter()` continues to call `FoxRig.partsForPose(pose)` without an editor override, so it resolves against the module's last saved active rest rig.
- Stage 4 IK/contact solving has not been started.

A full interactive browser smoke run could not be completed in the build environment because its Chromium policy blocks local/file navigation. Touch feel, actual Safari rendering, service-worker/A2HS upgrade behaviour and visual proportion judgement therefore remain explicit **physical iPhone tests**, not claimed validations.
